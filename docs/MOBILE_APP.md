# FinRatio as an installed app (iOS and Android)

The website is wrapped with [Capacitor](https://capacitorjs.com): the production web build (`dist/`) is bundled into a native
shell, so one codebase serves the web, Android and iOS. Nothing about the website changes.

## What is set up

| Piece | Where | Notes |
|---|---|---|
| Capacitor config | `capacitor.config.json` | JSON, not `.ts`, because the project has no TypeScript installed (Capacitor needs it to read a `.ts` config) |
| App identity | `appId: site.finratio.app` | **Permanent in both stores. Confirm before the first upload.** |
| Android project | `android/` | Generated by `cap add android`; commit it |
| Native startup | `src/lib/native.ts` | Status bar colour, Android back button, splash screen. Plugins load on demand, so the website never downloads them |
| Browser-only features switched off in the app | `isNative()` in `native.ts` | Service worker, "install this site" banner, popup Google sign-in |
| App origin | `server.hostname: app.finratio.site` | Allowed in the Supabase function's `ALLOWED_ORIGINS`. **The function must be redeployed for the app to reach it** |

## Everyday commands

```
pnpm exec vite build && npx cap sync android     # or: pnpm run app:sync
cd android && ./gradlew assembleDebug            # debug APK: android/app/build/outputs/apk/debug/app-debug.apk
pnpm run app:android                             # build, sync and open Android Studio
```

Needs JDK 21 and the Android SDK (platform 36). `android/local.properties` holds the SDK path and is not committed.
This repo's `node_modules` was installed with pnpm 10; use `npx pnpm@10.34.6 add ...` for dependency changes (pnpm 11 refuses its store).

## Mobile fixes made for the stores

- Money fields open the numeric keypad (`inputMode="decimal"`).
- Text fields are 16 px on touch devices, so iOS Safari does not zoom the page on focus.
- Headers and footers respect notches and the home indicator (`viewport-fit=cover`, `env(safe-area-inset-*)`).
- Larger tap targets on touch devices (theme toggle, home page header and footer links).

## Still to do before a store submission

1. **Release signing (Android).** Create an upload keystore, store it and its password somewhere safe (losing it blocks updates), build a signed `.aab`.
2. **Sign in.** Google popup sign-in does not work inside an app and is hidden there. Add native Google sign-in, and **Sign in with Apple** (Apple requires it when other social logins are offered).
3. **iOS build.** Needs a Mac or a cloud macOS build service, plus an Apple Developer account. `cap add ios` has not been run.
4. **Hide "Coming soon" screens** (Document Parser, CMA Generator) in the store build; Apple rejects placeholder features.
5. **Native value for Apple's review** (guideline 4.2): for example native share/export of results, offline history, biometric unlock.
6. **Store paperwork:** Apple privacy labels, Google Data safety and financial-features declarations, AI data-sharing disclosure, a demo account for reviewers (access is invite-only), screenshots, 1024 px icon.
7. **Redeploy the Supabase function** with the new allowed origins.
8. Remove the unused `VITE_OPENROUTER_API_KEY` from your local `.env` (nothing reads it and it is not in the bundle, but `VITE_` values are meant to be public).
